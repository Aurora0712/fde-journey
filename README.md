# FDE Journey — 90 天把 AI 落地成生产力

> 主线项目：**道路养护智能助手**
> 巡查记录 / 病害照片 → 结构化病害登记 → 依据规范给出养护建议 → 生成工单与报表
> 起止：2026-09-30 → 2026-12-28 ｜ 每天 1–2 小时，每周 6 天 + 周日复盘

## 这个仓库是什么

不是代码仓库，是**交付证据链**。90 天后打开它，应该能清楚回答三个问题：

1. 我发现了什么真实问题（审计表、访谈笔记、ROI 测算）
2. 我怎么判断该不该用 AI、用到什么程度（链路图、模式选择、gate 设计）
3. 我怎么证明它有效（黄金数据集、eval harness、前后耗时对比）

代码只是其中一环。**问题定义、流程设计、评估方法、领域判断**——这些才是 FDE 真正的核心，也是这个仓库里最值钱的部分。

## 目录结构

```
00-准备/     环境搭建笔记、工具选型、踩坑记录
01-审计与设计/  审计表、链路图、决策说明、一页纸  ← Day1-2 产出放这里
02-数据与标注/  黄金数据集、失败案例集、数据地图  ← 最核心资产
03-代码/      脚本（按周分子目录）
04-评估/      eval harness、评分器、通过率记录
05-部署/      Dockerfile、部署文档、可观测性记录
06-复盘/      每周复盘 + 每周日 90 秒语音的文字稿
99-草稿/      临时想法，随时清理
```

## 每日提交（三条命令）

```bash
git add .
git commit -m "D1: 完成养护流程审计表 v0"
git push
```

**Windows 用户可以直接双击 `daily-push.bat`**，输入一句话说明后自动完成 add → commit → push。

## Commit message 规范

统一用 `D<第几天>: <做了什么>`，例如：

```
D1: 完成养护流程审计表 v0，圈定主攻流程
D10: 建 20 条黄金数据集第一轮标注
D45: RAG 问答系统接入养护规范，20 问对 15
```

**为什么要在意这个**：90 天后这条提交历史就是你的学习曲线，也是你在面试/考核里能拿出来讲的证据链。写得越具体，将来越好讲。

## 三条硬规矩

1. **每天必须有产出物**——哪怕只有一张表。没产出的那天算没学。
2. **卡住超过 30 分钟就标记、跳过**，第二天带着具体问题解决。带着问题前进本身就是 FDE 的能力。
3. **每周日 30 分钟**：向一个完全不懂技术的人讲一遍本周做了什么。讲不清就是没想清。
